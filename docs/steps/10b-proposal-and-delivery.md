# 第 10 阶段申请书对照与 TraceRAG 交付

日期：2026-10-03。依据项目申请书、步骤 1–9 记录与本阶段代码工作整理。申请书作为需求依据；人员信息与预算不写入代码仓库。本文区分已有工程能力、研究结果和仍需真实输入的工作。

## 1. 申请书目标与本阶段范围

申请书提出接入运维文档、告警截图、日志、时序指标、网络拓扑和历史案例，构建统一事件表示与 Doc / Log / Metric / Topo / Case 检索，融合 BM25、Dense、重排及拓扑证据，输出根因候选、证据链、影响范围和处置报告。低资源模式应能在 CPU 环境构建原型；增强模式再使用云模型或独立 GPU 环境。

申请书的时间表包含：2026 年 9–12 月完成系统及至少 5 类网络故障演示，2027 年 1–3 月使用 30–50 条问题/样例进行分项评测，2027 年 4 月整理结题材料。现有微服务基准不能直接替代光纤中断、端口 Down、ONU 离线或光功率异常的真实网络运维验证。

用户当前指定链路为“时序数据 → 时序异常检测 → 根因定位 → RAG 检索 → 日志工单”。本阶段沿用已完成的算法和契约，补一条可脱离网页运行的 CLI、外部 RCA 环境自检、检测实验参数入口、TraceRAG 命名和中文安装说明。工单交付仍是待人工审核的草稿；运行日志仅用于审计。

## 3. 已有实测结果及其含义

第 9b 阶段保留 OB / SS / TT 各 125 例的系统划分，总计 375 个样本，两种触发方式形成 750 条评分。TT 的 annotation-trigger 服务 Hit@1 为 59.2%；detector-trigger 首告警全部早于目标注入，及时告警且首位根因正确的端到端 Hit@1 为 0%。该结果说明应优先检查检测与预处理，不能通过引用审计或网页功能宣称诊断精度可用。

`causal_ffill5_zero_v1` 的剩余缺失填零可能制造变化；前段基线也没有独立标签证明为正常。含故障文件里的提前报警不能当作独立纯正常数据的误报率。后续改进必须保留旧协议和失败结果；TT 已被查看，不能在观察结果后调参并重新称其为未见测试。

第 9c 阶段正式人工案例、相关性标注、陈述支持标注均为 0，语义质量指标为 `null`。`examples/` 的教学 case、测试模拟审核、助手工程检查和故障注入标签，均不能替代真实已确认处置案例。

第 9d 阶段仅一个真实 RE2 事件完成多源接入；图像来自同一指标窗口的绘图，日志和调用链提供 RAG 证据，RCA 仍是指标 BARO。9 组配置各重复两次验证的是门禁、配置与来源留痕。不同预算配置之间不能把所有差异归因于模态；只有等预算的 multisource 与各 without_* 适合隔离单来源。

这些结果来自步骤 1–9 已保存的记录，不能直接计作本轮改动的测试证据。完整数据、口径和产物位置见 [9b](09b-preprocessing-and-baseline.md)、[9c](09c-knowledge-and-review.md)、[9d](09d-multisource-and-test.md)。

## 4. TraceRAG 源码交付边界

TraceRAG 保留上游 MIT 许可证、EasyRAG 作者归属和论文引用，内部包名 `easyrag` 保持兼容。两项目依旧独立：TraceRAG 编排外部 RCA CLI，信号包成为唯一数据交界；RCA 的源码、vendor、算法依赖和测量数据不由 TraceRAG core requirements 打包。

交付采用干净源码快照，不包含下载的外部数据、旧 outputs、knowledge 版本、密钥、个人配置或既有 Git 历史。安装基线为 Windows / Python 3.12 的 `requirements-windows-core.txt`，默认 CPU + BM25 + 摘录草稿。干净克隆可以先运行教学文档问答、后端单元测试及前端生产构建；五段真实 CSV 链路需要兼容 RCA 工程、对应 Python 和输入文件。

一条命令的流水线应保存输入/配置/代码指纹、事件、语料快照、证据包、草稿、运行状态和独立审计；每次创建新目录。无事件、未完成观测窗口或外部 RCA 失败需要明确状态，不能继续生成缺少依据的草稿。检测参数入口改变的是实验可配置性，没有修改算法或承诺效果改善。
