记录日期：2026-09-27。前置：[9a 数据准备](09a-data-readiness.md)、[9b 批量基线](09b-preprocessing-and-baseline.md)、[9c 知识与人工审核](09c-knowledge-and-review.md)、[9d 独立测试与多源接入](09d-multisource-and-test.md)。

## 1. 对用户问题的直接回答

**每次查询的 manifest 不是“以前所有文档 + 本次完整 RCA 结果/回答”的自动累积文件。** 当前实现使用“已发布长期知识的适用子集 + 当前事件的观测”组成查询快照。RCA 候选在事件对象内参与查询扩展；回答和工单单独保存，不能未经核验变成历史案例。

**全局入口现在是 `D:\Project\EasyRAG\knowledge\active.json`。** 它指向 `knowledge/versions/kb-.../manifest.jsonl`，当前登记 23,339 条 AIOps 文本和 9 条按系统声明范围的微服务手册记录。查询按 system 隔离，一次微服务诊断不会把整套电信资料加入语料。

`outputs/knowledge_builds` 保存各来源的构建结果；`outputs/signal_imports/import-.../corpus/manifest.jsonl` 保存某次事件导入时的快照。二者都不是自动查找全部历史数据的总库入口。本轮之前没有独立的 active 注册机制，9a 的 AIOps 库也尚未接到默认网页；这次已经补齐。

**RCA 与 EasyRAG 已有实际联动。** 新控制台上传 CSV 后调用 RCA 的 `scripts/run_signal_workflow.py`，产生信号包，导入事件和摘要，随后检索并生成待审核工单。默认在 EasyRAG 的同级目录寻找 RCA，也可用 `--rca-root` 指定其他位置。同级放置只便于默认发现，仍需 Python 环境、RCA vendor 与依赖、已构建前端，并启动新控制台。不要合并两套 `src`；旧 Streamlit UI 不是这套新入口。

```powershell
cd D:\Project\EasyRAG
```

前端本轮已构建；修改前端后在 `web/` 下运行 `npm run build`。新环境依赖及首次 `npm ci` 见第 8 阶段说明。

| 知识/正式案例 | 打开“知识与案例”，只有真实核验和实际处置才能提交正式案例 |
| 人工评分 | 工单页分别填写检索相关性和陈述支持度 |

当前版本 `kb-305444bbb768a43d7d16bf7a6ea7df0e`，正式真实案例 **0**。AIOps 查询会建立较大的 BM25 索引，本轮实测已完成查询，但未把单次耗时当延迟基准；索引复用仍是后续性能工作。
