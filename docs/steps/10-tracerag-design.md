## 实施设计

沿用 RCA 与 RAG 独立、JSON 契约连接的既有架构。新增本地流水线 CLI：接收显式 CSV 或已保存信号包，调用 RCA CLI，检查事件是否可分析，然后生成事件快照、证据包和结构化工单，最后独立核验引用与产物。没有报警或观测窗口未完成时保存明确状态，停止进入检索和工单生成。

流水线默认离线，不通过网页服务，不修改长期知识库指针，不把工单自动转为历史案例。每次运行新建目录，保存状态和输入指纹；原始路径仅保存在私有记录中。外部 RCA 项目使用显式路径与 Python 环境，缺失时给出可操作提示。

网页和 API 补充预热点数、连续确认点数、最少指标数和时间间隔上限，与 RCA 现有配置保持一致。这些是实验参数入口，不是检测算法改进结论。

重新编写中文 README，更新 TraceRAG 展示名称；保留 `easyrag` 内部包名和上游许可证以兼容既有接口。在信号转换、证据过滤/融合、工单校验和文件编排处添加少量解释设计意图的中文注释。

发布采用干净源码快照：在 `D:\Project\TraceRAG` 建立新的 Git 仓库，不把原项目历史、下载数据、输出、个人设置或密钥传上 GitHub。保留原工作目录及已有修改，便于继续查阅历史产物。用户已授权创建私密仓库并上传，选择名称不需要再确认。
