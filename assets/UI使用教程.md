## 1. 先认识页面里的对象

控制台的基本链路是：**时序 CSV → 检测和 RCA → 事件 → 检索证据包 → 工单草稿 → 人工修订**。 日志、调用链、拓扑和图片图注是另行附加的事件观测；正式案例需要实际调查与处置后再登记。

| 对象 | 内容 | 页面入口 / 用途 |
|---|---|---|
| 原始时序 CSV | `time` 和数值指标；不含算法结论 | 诊断工作台 → 上传 CSV |
| `signal-bundle.json` | 检测、分析窗口、RCA 候选、指标摘要、配置及指纹 | 诊断工作台 → 导入信号包 |
| 运维事件 | 由信号包转换的 `IncidentDocument` | 工作台“事件”下拉框 |
| 观测证据 JSON | 同事件的结构化 log / trace / topology / image 及原资产 | 知识与案例 → 导入观测证据 JSON |
| 查询语料快照 | 本次提交时固定的适用知识与观测 | 后端留存；实验记录显示关联信息 |
| 检索证据包 | 最终证据、原文、排名、来源、路由、配置和指纹 | 本次结果 / 工单右侧证据原文 |
| 工单草稿 | 摘要、未确认候选、验证步骤、未执行建议及引用 | 工单与复核 |
| 人工修订 | 草稿正文修改、逐条支持判断、复核意见和版本关系 | 工单与复核 → 保存人工修订 |
| 正式历史案例 | 已确认根因、实际处置、实际结果和核验记录 | 知识与案例 → 正式历史案例 |

页面中的 `import-...` 是导入记录 ID，`inc-...` 是领域事件 ID，`job-...` 是网页任务 ID。 `run-...` 对应检索运行，`pack-...` 对应证据包，`gen-...` 对应生成记录，`rev-...` 对应人工修订。 这些对象分别保存，不能把一个 JSON 随意交给另一个入口。

## 2. 启动和进入页面

### 2.1 本机已有环境

在 PowerShell 中从项目根目录启动，保持这个进程运行：

```powershell
Set-Location 'D:/Project/EasyRAG'
& 'D:/miniconda/envs/fastapi_env/python.exe' src/operations_console.py `
  --rca-root 'D:/Project/RCA' `
  --rca-python 'D:/miniconda/envs/fastapi_env/python.exe'
```

浏览器打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。页面只连接本机服务。 若使用自己的虚拟环境，将两处 Python 路径替换为实际解释器；RCA 可以使用独立解释器。 若改端口，加 `--port 8766`，浏览器也访问相同端口。 停止时回到服务终端按 `Ctrl+C`；重新启动后刷新网页。

### 2.2 首次准备环境

已有环境无需反复安装。干净 Windows 环境的安装入口是项目 README 中的 Python 3.12 / Node.js 24 配置：

```powershell
Set-Location 'D:/Project/EasyRAG'
py -3.12 -m venv .venv
$env:PYTHONIOENCODING = 'utf-8'
.\.venv\Scripts\python.exe -m pip install -r .\requirements-windows-lock.txt
npm.cmd --prefix .\web ci
npm.cmd --prefix .\web run build
```

控制台服务的是 `web/dist`；改前端源码后要重新构建、重启服务并刷新。 默认离线检索不要求启动 Qdrant、不要求下载本地大模型。 CSV 功能还需要配套 RCA 的 `scripts/run_signal_workflow.py`、算法依赖和固定源码；仅安装 EasyRAG 依赖不够。 没有 RCA 时可以使用已有信号包及文档检索。“处理并导入”不可用时先核对 `--rca-root`。

干净克隆不带本机 `data/`、`outputs/`、`knowledge/`、密钥或个人设置，所以不会带出旧事件和工单。 没有 `knowledge/active.json` 时存在教学语料兼容入口；页面的知识版本、系统列表以实际加载结果为准。

## 3. 页面入口

| 入口 | 能做什么 | 推荐操作顺序 |
|---|---|---|
| 诊断工作台 | CSV / 信号包导入、选事件、选知识来源、配置实验、提问、查看证据 | 导入 → 选事件 → 配置 → 提问 |
| 工单与复核 | 选历史工单、读原文引用、改正文、判断支持、保存与下载修订 | 先读引用，再改与标注 |
| 实验记录 | 看任务阶段、错误和完整记录；选 2–4 份工单比较 | 同问题同事件控制变量比较 |
| 知识与案例 | 看知识版本与数量、附加观测、人工登记正式案例 | 先在工作台选好事件 |
| 运行日志 | 按错误 / 警告 / 信息筛选，查看任务 ID、阶段和提示 | 失败时与实验记录对照 |
| 设置 / 右上角离线或 Cloud 状态 | Cloud 总开关、默认生成服务、模型凭据、代理和超时 | 保存设置后再选实验能力 |
| 左侧最近工单 | 快速打开最近 7 份生成记录 | 进入同一工单复核界面 |

左栏可收起和展开。页面时间均标为 **UTC**；北京时间为 UTC 加 8 小时。 右上角“Cloud”表示总开关允许云能力，不表示本次任务所有环节都使用了云服务。 “未连接”表示浏览器不能连接本地服务，恢复后页面会自动同步。

## 4. 上传 CSV：检测、RCA 与事件导入

### 4.1 CSV 必须满足的条件

- 文件不超过 **6,000,000 字节**（页面写“6 MB”），建议 UTF-8 编码。
- 有名为 `time` 的列，使用非负、严格递增、无重复的**整秒 Unix 时间戳**，不是日期字符串或毫秒。
- 至少有一列指标，指标为数值；严格模式拒绝空值、NaN、Infinity、文本和布尔值。
- 指标列名唯一；不允许 `label`、`labels`、`fault_type`、`ground_truth` 等评测标签列。
- 重复 `time` 只有**每行原始字符串完全一致**时才自动合并；重复指标或冲突时间列必须修正。
- 行列数齐整，列名非空；不要把目录里的故障名称当作额外指标。

```csv
time,redis_diskio,cartservice_latency-90
1705353900,3316.4,0.0051
1705353901,3400.2,0.0052
1705353902,3450.0,0.0052
```

以上仅展示格式，三行不足以完成默认检测和分析。实际文件必须覆盖预热与事件前后窗口。 RE1 的 `data.csv` 是指标数据，不能由它生成它没有包含的业务日志、trace 或真实处置记录。

### 4.2 上传步骤

1. 在“诊断工作台”点“上传 CSV”，选择文件。
2. 核对系统名称，让它与适用手册、观测及正式案例的 `system` 一致。
3. 先用默认参数运行；如需消融，另一次运行再改参数并记录理由。
4. 点“处理并导入”；等待“时序检测 → RCA → 指标摘要”，不要把排队中当作完成。
5. 完整事件导入成功后，页面自动选中新事件；展开事件详情核对来源、时间和证据截止。
6. 去“实验记录”展开任务“记录”，核对配置、状态及时间列合并计数。

### 4.3 每个参数的含义与默认值

| 页面参数 | 默认值 | 实际含义 / 使用注意 |
|---|---|---|
| 系统名称 | `online-boutique` | 标识事件适用系统；不是根因服务名 |
| 缺失值处理 | 严格校验 `strict` | 数值或时间不合规即拒绝 |
| 历史前向填充 | 可选 `causal_ffill5_zero_v1` | 最多前向填充 5 行，长于 5 秒的时间缺口重置，剩余空值补 0；保存审计 |
| 异常检测 | 开 | 使用前序预热拟合的 robust MAD 检测器寻找首告警 |
| MAD 阈值 | `6.0` | 偏离基线的归一化分数须大于阈值；降低通常更敏感，也可能增加误报 |
| 预热点数 | `300` | 前 300 个采样点作为固定基线，单位是点，不是秒 |
| 连续确认点数 | `3` | 单个指标连续超阈值至少 3 点才合格 |
| 最少异常指标数 | `1` | 同一时刻达到连续条件的指标至少 1 个 |
| 采样间隔上限（秒） | `5` | 相邻采样超过 5 秒，检测连续计数清零；不会补采样 |
| 人工事件时间 | 默认空 | 关闭检测后必填整秒 Unix 时间；开启检测时清空，由检测器决定时刻 |
| RCA | 开 | 是否运行根因候选排序；关闭仍可保留检测和指标摘要 |
| BARO | 开 | 配套 RCA 中的指标排序方法；结果是候选 |
| ε-Diagnosis | 关 | 另一可选 RCA 方法；需要对应依赖和可比较窗口 |
| 指标摘要 | 开 | 从限定窗口生成可检索指标观测；默认最多 10 条 |

页面校验范围：MAD 阈值大于 0 且不超过 1000（输入控件最小 0.1）；预热 20–100000，连续点 1–10000，最少指标 1–100000，间隔 1–86400 秒。 最少异常指标数还不能超过实际可监控指标数；RCA 开启时至少选 BARO 或 ε-Diagnosis。 历史前向填充还会丢弃无效时间行、排除整个预热期都无有效值的指标，不自动排序或修复重复时间。 补零不是实测零，可能制造变化；核对 `preprocessing-report.json` 再解释结果。

窗口不是页面里的检测预热点数：当前配套 RCA 默认取事件前 **5 分钟**参考窗口和后 **5 分钟**观测窗口，每侧至少 **20 点**。 这些值来自 `D:/Project/RCA/configs/signal_workflow.yaml`，当前 UI 没有窗口编辑控件。 MAD 首告警是顺序回放结果，不保证等于数据集注入时间；BARO 首位也不保证真实根因。

### 4.4 没产生事件时

| 状态 | 原因 | 下一步 |
|---|---|---|
| `no_event` / 检测未报警 | 当前文件和参数未触发首告警 | 查看检测记录；不要宣称已经诊断正常或故障 |
| `insufficient_warmup` | 点数不足预热 | 补充前序数据或有依据地调整预热 |
| `awaiting_observation_window` | 首告警后的完整窗口尚未覆盖 | 补足数据覆盖后新建上传任务 |
| `insufficient_points` | 参考或观测窗口内点数不足 | 核对采样与覆盖；不要仅裁出异常尖峰 |
| `failed` | 输入、依赖、算法或超时错误 | 读实验记录和运行日志的具体提示 |

任务“已完成”可能只是完成检测且没有可用事件。只有分析 `complete` 才导入完整事件并用于 RAG。 修正后要重新提交；旧失败记录作为历史留痕保留，不会自动重算。

## 5. 导入信号包、选择事件和提问

### 5.1 “信号包”是哪份文件

选择配套 RCA 实际生成的 **`signal-bundle.json`**，不是 `incident.json`、`normalization-report.json`、`job.json` 或任意结果 JSON。 网页 CSV 任务的文件位于：

```text
D:/Project/EasyRAG/outputs/console/jobs/job-<ID>/signals/signal-run-<ID>/signal-bundle.json
```

直接在 RCA 执行信号 CLI 时，文件位于其指定输出目录的 `signal-run-<ID>/signal-bundle.json`，常见为 `D:/Project/RCA/outputs/...`。 在工作台点“导入信号包”并选择该文件，限制 **8,000,000 字节**；通过格式和转换校验后新增事件。 同一包重复导入可以生成不同 `import-...` 记录。事件的首次导入快照各自留存。

### 5.2 已选事件的问题

1. 下拉选择 `系统 · inc-... · 导入 ID 尾号`，确认不是同包的另一条旧导入。
2. 展开事件详情，看检测来源和时间；`anomaly_detector` 与人工触发的语义不同。
3. 选择知识来源，展开实验配置，输入具体问题。
4. 点输入框右侧箭头，或按 `Ctrl+Enter`（Mac 为 `⌘+Enter`）。
5. 读最终证据与工单，再做人工复核。

推荐问题：“当前异常有哪些候选原因？逐项给出已有依据、缺失验证以及处置前提。” 也可问：“Redis I/O 上升能支持什么观测结论？哪些因果解释目前缺少日志或调用链？” 问题最多 10000 字符。提交后服务读取已保存事件，不重新上传 CSV，也不重新运行 RCA。 切换事件会清空当前结果编辑区；已保存的工单和修订仍能在历史入口打开。

### 5.3 没有事件时的问题

选“运维文档问答（无事件）”，再选“文档范围”中的系统。 例如：“checkoutservice 延迟升高时，手册建议先收集哪些信息？” 此模式只用适用系统的运维手册，不包含当前故障指标、RCA、事件附件或历史案例。 不要要求它确认本次故障、当前影响范围或现场根因；文档问答可以解释方法，但缺少当前现场事实。

## 6. 当前知识库与导入时快照

| 选择 | 使用内容 | 何时使用 |
|---|---|---|
| 当前知识库 + 本事件观测 | `knowledge/active.json` 指向的当前手册/案例版本，加本事件指标与后来附加观测 | 新证据上传后继续调查 |
| 导入时快照（复现实验） | `outputs/signal_imports/import-.../corpus/manifest.jsonl` | 固定当时知识重现实验 |

例：昨天用 V1 导入事件，今天发布 V2、附加同事件日志。当前模式使用 V2 和新日志；导入时快照仍用 V1 与当时观测。 当前模式也在**提交查询时**冻结独立快照；排队期间新发布知识不会改变已经提交的这次查询。 新增观测不会修改旧工单、旧证据包或旧查询；必须在当前模式下重新运行才能看到它。

两种模式都保留适用性门禁：系统一致、观测属于同事件、窗口相交、结束时间不超过证据截止。 历史案例必须人工核验，排除当前事件自身案例，也排除核验时间晚于事件发生时刻的案例。 今天审核的 2023 年事故可以服务符合规则的未来事件，不能回填为 2023 年实验当时已有的知识。 尚未登记长期库时存在兼容行为，先看知识页面版本；正式使用应准备并登记真实适用手册。

## 7. 实验配置逐项说明

### 7.1 页面可直接修改的开关

| 配置 | 默认 | 对结果的作用 |
|---|---|---|
| 运维手册 / 历史案例 / 时序指标 | 开 / 开 / 开 | 启用对应证据路由；案例仍须符合核验与时间门禁 |
| 日志 / 调用链 / 拓扑 / 图片图注 | 全关 | 有同事件合格附件时才有内容；开启不会凭空生成证据 |
| RCA 候选扩展查询 | 开 | 每种 RCA 方法取前 3 个候选扩充关键词；不是直接把候选当证据 |
| 文档路径检索 | 开 | 增加知识层级路径的匹配路由，不是搜索磁盘文件路径 |
| RRF 排名融合 | 开 | 用各路名次融合；关闭时按路由确定性轮询合并，不横比原始分数 |
| 检索模式 | BM25 | BM25 词项匹配；Dense 语义向量；Hybrid 结合两者 |
| 云端重排 | 关 | 召回后用 Qwen `gte-rerank-v2` 重新排序候选 |
| 最终证据条数 | 6 | 最终上限；资格、召回、去重及字符预算可能使实际更少 |
| 生成草稿 | 开 | 关闭只留检索与生成禁用记录，不产生诊断正文 |
| 生成时提供 RCA 候选 | 开 | 在生成输入里提供候选；与检索侧 RCA 开关独立 |
| 生成模式 | 离线证据摘录 | 不调用生成 API；Cloud 才使用选择的 Qwen / GLM |

### 7.2 消融预设

选预设会重置检索与生成为启动默认值，再应用该预设；先选预设，再做个别修改。

| 预设 | 改动 |
|---|---|
| 离线基线 | 恢复启动默认值，通常 BM25 + 离线摘录 |
| 多源证据（最多 20 条） | 七类来源全开，证据上限 20，字符预算 40000 |
| 检索与生成不使用 RCA 候选 | 关闭检索 `use_rca` 与生成 `include_rca_candidates` |
| 仅手册证据 | 只开 doc 路由；生成仍按配置，若需同时排除 RCA 要另关生成开关 |
| 关闭路径检索 | 仅关闭路径路由 |
| Hybrid | 启用 Hybrid 及 Embedding；须先开启 Cloud |

预设是实验组合，不是保证更准确的“最佳模式”。不同证据条数 / 字符预算的比较需说明预算差异。

### 7.3 高级配置 JSON

展开“高级配置 JSON”会同步当前配置。修改后点“应用 JSON”，看到后端校验通过提示才算应用。 顶层必须是 `retrieval` 与 `generation`；不要把模型 Key、服务地址或文件路径写进这里。

1. 点左下“设置”或右上状态，进入“通用”，开启 Cloud 模式并选择默认生成服务。
2. “模型服务”中输入对应 Key、模型和 Qwen 地域；留空保留已有密钥，勾“清除”会停用它。

| 能力 | 服务 | Cloud 开后是否自动启用 | 输入边界 |
|---|---|---|---|
| BM25 | 本地 | 默认可用 | 本地适用语料 |
| Dense / Hybrid 的向量部分 | Qwen `text-embedding-v4` | 否，要选模式 | 检索查询、待编码的合格正文 / 知识路径；已有缓存可复用 |

## 10. 工单复核：怎样改、怎样判断支持

### 10.1 具体操作

1. 在“工单与复核”选历史工单，确认 `gen-...`、事件及 `pack-...`。
2. 左侧每条摘要 / 候选 / 验证 / 建议下面点引用按钮，右侧会滚动并高亮对应原文。
3. 核对完整原文、来源和元数据；引用文本存在只是结构校验，还要判断它是否支持这句话。
4. 在该条文本框修改正文。编辑会将本条支持判断重置为“不确定”，之后重新判断。
5. 逐条选“证据支持 / 证据不支持 / 不确定”，填写复核人和复核意见。
6. 有任何不确定或不支持时选“仍需修订”；所有条目均支持才允许“已复核草稿”。
7. 保存前移除所有正文中的具体 shell 命令或可执行脚本，改成有证据依据的描述式验证步骤；然后点“保存人工修订”，看到新的 `rev-...` 后下载或在“已保存版本”继续修订。

当前 UI 编辑的是陈述正文，**不能直接增删条目、替换引用、修改候选验证说明或建议的前提 / 风险 / 回退字段**。这些字段在页面显示供核对。需要补齐或改变它们时，先将本条标为需修订、写明意见，再补知识并重新生成。若不可编辑字段中含具体命令而无法通过校验，应重新生成合规草稿；单独标“不支持”不能绕过结构、引用或命令校验。不要把“前提未满足”的变更建议改成已经执行。页面、下载的文档都不会执行其中命令。

| 支持标记 | 应何时选 |
|---|---|
| 不确定 `uncertain` | 尚未核验、上下文不足，无法下支持结论 |
| 证据支持 `supported` | 当前引用原文能支持修订后的完整表述，且适用系统 / 时间成立 |
| 证据不支持 `unsupported` | 引用与论点错配、遗漏必要条件，或论断超过证据内容 |

“可能”“建议验证”不能自动使一条有引用的论断获得支持。候选解释也需要区分观测事实与推测。 “已复核草稿”仍保存为根因未确认、动作未执行、未提升案例；复核身份为本地自报身份。

### 10.3 前提、风险与回退的好坏写法

坏例：“Redis I/O 高，立即重启 Redis。”它缺少根因核验、业务审批、恢复保证和适用依据。 假设已经取得适用手册与现场证据，较好的**待审批建议**应分别说明：

- 前提：目标实例与系统已核对；真实日志证实相关机制；已获审批；已确认备份及恢复条件。
- 风险：可能导致短时不可用、缓存丢失或复制延迟；不能用一句“无风险”代替分析。
- 回退：给出可验证的恢复步骤和观察指标；不可声称已经回退或已经恢复。
- 引用：手册支持动作方法，现场证据支持为何需要动作；二者不能互相替代。

以上只是填写原则，不是针对附件事件的操作授权。当前草稿的生成和人工修订均拒绝明显具体命令或可执行脚本；原始手册引文可以保留命令原文。需要实际运维命令时，由现场人员依据适用手册在独立审批与执行流程中处理。

## 12. 观测证据 JSON 的准备与导入

### 12.1 顶层格式与字段

这是人工 / 脚本准备的结构化包。顶层必须且只能是 `documents` 和 `assets`。 下面是**结构示意，不能原样上传**：占位的事件、时间、SHA256 和 Base64 必须换成真实值。

```json
{
  "documents": [
    {
      "schema_version": "1.0",
      "knowledge_id": "obs-log-unique-revision-001",
      "knowledge_type": "log",
      "title": "当前事件的日志窗口摘要",
      "content": "真实日志窗口的简明观测；注明条数及筛选方法，避免把推断写成事实。",
      "source": "真实采集来源或记录编号",
      "raw_ref": "asset:<真实64位sha256>#<行号或时间筛选条件>",
      "metadata": {
        "system": "online-boutique",
        "source_incident_id": "inc-实际事件ID",
        "window_start_utc": "替换为真实ISO8601时间",
        "window_end_utc": "替换为真实ISO8601时间",
        "asset_sha256": "替换为原始资产字节的64位小写SHA256",
        "asset_media_type": "text/plain",
        "derivation": "真实提取方法，例如时间过滤后按消息统计频次"
      }
    }
  ],
  "assets": [
    {"sha256": "与metadata相同的真实SHA256", "base64": "原始资产字节Base64"}
  ]

```

`documents` 为 1–100 个实际对象，只接受 `log/trace/topology/image`；每份正文不超过 8000 字符。 `knowledge_id` 需唯一，符合小写字母开头、数字及 `._-` 的规则；重复 ID 要用新的修订 ID。 窗口起点早于终点、与事件窗口相交，终点不晚于 `evidence_cutoff_utc`；系统与 `source_incident_id` 必须匹配。 观测 `source_incident_id` 填领域 ID `inc-...`；上传目标 URL / CLI 的 `--event-id` 填导入 ID `import-...`。 SHA256 对应**原始文件字节**；后台会核对 Base64 解码后的哈希。不能把摘要字符串哈希冒充原资产。 原资产已登记在本机时 `assets` 可为 `[]`；否则需要提供对应资产。图片仅支持 PNG/JPEG 的页面预览。 图片检索使用图注文字；本入口不自动 OCR、不自动视觉诊断。

```powershell
Set-Location 'D:/Project/EasyRAG'
# 仅在固定 RE2 数据和可选 Parquet 依赖已经准备好时运行。
& 'D:/miniconda/envs/fastapi_env/python.exe' src/prepare_multisource_demo.py `
  --data 'D:/Project/EasyRAG/data/external/rcaeval-re2' --rca 'D:/Project/RCA'
```

使用打印 / 保存的 `report.json` 中**新事件 ID**；它创建另一事件，不会自动附到你此前选择的 RE1 事件。 历史 RE2 样例 `demo-2f2384023f4541689bc39aff32c4104a` 是阶段记录中的本机实例，是否仍存在须实际检查。 RE2 `traces.parquet` 约 10 MB，Base64 后更大；网页 **8,000,000 字节**总请求限制，宜走本地资产入口。

### 12.3 为已经选择的事件附加已准备清单

先确保清单内事件、系统与窗口均对应目标事件，再执行；可以重复 `--asset` 参数登记多个原资产。

```powershell
Set-Location 'D:/Project/EasyRAG'
& 'D:/miniconda/envs/fastapi_env/python.exe' src/attach_event_evidence.py `
  --event-id 'import-替换为真实导入ID' `
  --manifest 'D:/实际目录/observations/manifest.jsonl' `
  --asset 'D:/实际目录/observations/original.log'
```

该命令**直接保存附件**，不是导出供网页上传的文件；`--asset` 不会自动解析日志或创建清单。 若选择网页路线，需要自行将清单对象与 Base64 原资产封装成上述包，保存为 `event-evidence.json`。 从“诊断工作台”选好事件，再去“知识与案例”点“导入观测证据 JSON”，选包装文件。 成功后会显示新增观测条数与批次 ID；回工作台选择当前知识来源，并启用所需来源后重新提问。 不要将“信号包”“工单 JSON”“原始 CSV”“任意日志文件”塞入此按钮，它不是通用文件解析器。

## 13. 正式历史案例：实际核验后另行入库

正式案例在“知识与案例”右侧填写；保存人工修订不会自动入案例库。 先回工作台选择正确事件，再核对知识页面提示的当前事件与长期库版本。

| 表单字段 | 应填写的事实 | 不合格填写 |
|---|---|---|
| 案例标题 | 已核验事故的简明标题 | “测试”“随便填” |
| 审核人 | 实际核验者姓名或可追溯标识 | 冒充其他人 |
| 观测症状（每行一项） | 有现场记录的变化及窗口 | 复制算法候选作为症状 |
| 人工确认的根因 | 已完成调查并有依据的原因 | “BARO 第一所以是根因” |
| 已执行的处置（每行一项） | 实际执行动作及必要关联记录 | 把草稿建议写成执行结果 |
| 处置结果 | 真实监测或现场确认的结果 | 未观察就写“恢复正常” |
| 根因及结果核验依据 | 监控/日志定位、外部工单号、真实执行和复验记录 | 只有模型回答或目录故障名 |

确认所有事实与记录后，勾“我已人工核验以上内容，所填处置实际执行，依据可追溯”，点“保存审核并发布案例”。 需要已登记长期库、已选事件及完整必填项。审核时间由页面使用当前时间；服务端要求在当前时间 **±10 分钟**内，禁止回填旧日期。 服务会留下原提交、转成案例文档，并发布“当前长期库 + 新案例”版本；旧版本保留。 该入口记录本地人工声明，没有外部身份认证，也不自动核验依据字符串指向的外部记录。

正式案例包含：源事件 ID、系统、标题、症状、确认根因、实际动作、结果、依据、审核人和真实审核时间。 网页当前传入的 `rca_candidates` 是空数组；它**不自动复制**本次问题、RCA 结果、检索排名 / 分数、完整证据包、prompt 或工单。 需要追溯时，在依据中明确填写真实 `import/inc/gen/pack` ID 与实际监控或外部处置记录号。 原 RCA 保留在事件 / 信号包，检索和草稿另保存。案例记录不能替代这些实验文件。 不能只凭 RE1 目录名、故障注入标签、候选排行或本教程例子创建“已确认事故”；当前教程不登记真实案例。

下表均相对 `D:/Project/EasyRAG`。`<ID>` 为本次真实 ID，不是可以照抄的目录名。

| 类别 | 服务器保存位置 | 主要内容 |

人工修订 JSON 保存修改后的草稿、逐条支持判断、复核人、意见、状态、父版本与原记录哈希及修订哈希。 它不覆盖原工单、不新增完整原始 CSV 或观测资产、不修改原检索排名，也不代表现场动作执行。 生成失败时可能只留下 `audit.jsonl` 与关联失败任务，没有可下载的草稿；不要看到 `gen-...` 目录就断言成功。 `.private` 是用途命名，**不是加密**；原始文件和证据正文仍需按实际数据要求管理。

### 14.2 浏览器下载路径与格式

| 按钮 | 下载内容 | 默认文件名 |
|---|---|---|
| 原稿 Markdown ↓ | 原生成草稿的可读报告与引用 | `gen-<ID>.md` |
| 原稿 JSON ↓ | 原 `WorkOrderRecord`，含草稿、最终证据、配置、来源等 | `gen-<ID>.json` |
| 修订稿 Markdown ↓ | 已保存人工修订报告，含复核意见与支持标记 | `rev-<ID>.md` |
| 复核 JSON ↓ | 已保存 `review.json`；关联原生成记录 | `rev-<ID>.json` |

这些按钮下载到**浏览器设置的下载目录**，本机默认通常是 `C:/Users/DELL/Downloads`，与服务器 `outputs` 路径不同。 浏览器开启“每次询问保存位置”时以实际选择为准；修改下载副本不会写回服务端。 正文还没保存时，“原稿”按钮仍下载原稿；要拿修改后版本，先保存修订再点修订下载。 Markdown 便于读和分享；JSON 用于程序审查与评测。完整检索路由在 `evidence-pack.json`，不能把下载工单 JSON 当作它。 当前页面没有给正式案例、证据包、观测资产提供同样的一键 JSON / MD 下载按钮，按上表查服务端文件。

## 15. 完整操作示例与常见问题

### 15.1 一次可复现的人工操作

1. 启动本地服务，上传真实数值 CSV，保留默认检测、BARO、指标摘要。
2. 等待完整事件导入，抄下任务 ID 和导入 ID；不要把首告警和排名认作真实根因。
3. 选“当前知识库 + 本事件观测”，问“哪些变化被证据支持、哪些解释仍待验证”。
4. 保存 / 下载原稿，进入工单逐条检查引用；对错配和过度推断修改正文或标不支持。
5. 保存“仍需修订”或所有条目支持后的“已复核草稿”，分别下载修订 MD 与 JSON。
6. 有真实同事件日志等时按契约附加，开启对应来源，重新运行；比较两次证据与草稿。
7. 做消融时改一个配置并固定其余条件，在实验记录选择 2–4 份工单对照。
8. 只有完成真实现场调查、执行和复验后，才另行填写正式案例。

### 15.2 常见问题定位

| 现象 | 核查 / 处理 |
|---|---|
| 页面一直“正在连接本地服务” | 服务终端是否运行、端口是否正确；重启正确目录服务并刷新 |
| CSV 按钮灰色 | 是否已选文件、服务是否发现配套 RCA 脚本 |
| 重复 time 报错 | 必须逐行字符串一致才合并；冲突不能改名为指标绕过 |
| 时间校验失败 | Unix 秒而非毫秒、严格递增、无重复；不要依赖程序自动排序 |
| NaN / 非数值错误 | 核对输入；若启用历史填充需审查报告及补零影响 |
| RCA 方法错误 | 至少选择一种；ε-Diagnosis 需要依赖及适用的窗口条件 |
| 上传结束但下拉没新事件 | 查看 `analysis` 和 `rag_ready`；可能是未报警或窗口不足 |
| 开启 log/trace 后无证据 | 原 CSV 不含这些；确认附加到同 import 记录、选择当前模式、满足门禁 |
| 上传观测提示格式 / 哈希错误 | 顶层包装、真实对象、资产字节 SHA256、事件 / 系统 / 时间，逐项核对 |
| 8 MB 超限 | 含 Base64 的整个包计入限制；大资产走本地 `--asset` |
| Cloud 能力不可选 | 先设置 → 通用开启并保存；再设置本次实验开关 |
| 已保存 Key 仍失败 | 查看服务、地域、HTTP 状态；401/403 鉴权，429 额度或限流，超时查代理和网络 |
| JSON / 引用校验失败 | 模型输出不符合结构或引用；核对审计、预算和证据；不要当作可接受草稿 |
| 高级配置应用失败 | 类型、范围、额外字段、Embedding 与模式一致、重排候选覆盖 top_k、两个留痕开关 |
| “已复核草稿”保存失败 | 仍有不确定 / 不支持条目；改为仍需修订或完成真实复核 |
| 旧结构归档不可编辑 | 该历史记录不符合现行契约；保留归档并新生成 |
| 案例保存 / 检索失败 | 先登记手册、选事件、填真实核验与结果；核验时间不要回填；旧事件排除新审核案例 |
| 原稿下载看不到修改 | 先保存人工修订，再下载修订按钮；原稿一直指向原生成记录 |

模型提供的是**依据现有证据的候选和调查建议**。指标相关、RCA 排名、引文可定位、相关性高，都不能单独确认故障根因。 “没有这类证据”也不等于“现场没有这类异常”；影响范围与业务损失缺少证据时保持未知。 本教程只说明使用与复核，不提交真实案例、不生成真实人工标注、不执行草稿中的运维命令。
